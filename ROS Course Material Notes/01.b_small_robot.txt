# Exercise — Build and inspect a small ROS 2 robot

## Purpose

This exercise creates a deliberately simple two-wheel robot and displays it in
RViz2. It is a learning exercise, not an ROV implementation and not a Gazebo
or hardware validation result.

The exercise proves the first part of the simulation toolchain:

```text
Xacro → URDF robot description → robot_state_publisher → TF → RViz2
```

It gives the learner a small, controllable model for understanding links,
joints, transforms, packages, builds, launch files, and visual inspection
before adding an underwater vehicle, simulated physics, NATS, or real hardware.

## Learning outcomes

By the end, you should be able to:

- create a ROS 2 package in the HiL/SiL workspace;
- describe a chassis and two wheels with Xacro and URDF;
- validate the generated URDF;
- build and source a colcon workspace;
- launch `robot_state_publisher` and `joint_state_publisher_gui`;
- inspect the robot and its transform tree in RViz2; and
- explain why this is only a model-description milestone, not a moving Gazebo
  vehicle.

## Scope and safety boundary

Use the independent Ubuntu HiL/SiL workstation. Do not connect the Raspberry
Pi, NATS Core, motor controllers, propulsion hardware, or a physical HID for
this exercise. Nothing here sends a command outside the local ROS 2 graph.

The workspace path is:

```text
~/ROV - HiL and SiL/ros2_ws
```

Because the repository name contains spaces, shell commands use `"$HOME/ROV -
HiL and SiL/..."`. Keep the quotation marks.

## Prerequisites

Complete Day 0 first. The Ubuntu VM should have ROS 2 Jazzy, RViz2, colcon and
the ROS environment available. Check the base installation in a new terminal:

```bash
source /opt/ros/jazzy/setup.bash
printenv ROS_DISTRO
ros2 --help
rviz2
```

`printenv ROS_DISTRO` should report `jazzy`, and RViz2 should open. Close RViz2
before continuing.

Install the packages used by this exercise if they are not already present:

```bash
sudo apt update
sudo apt install \
  ros-jazzy-xacro \
  ros-jazzy-robot-state-publisher \
  ros-jazzy-joint-state-publisher-gui \
  python3-colcon-common-extensions
```

## 1. Create the workspace and package

Create the workspace if necessary, source Jazzy, and create an `ament_cmake`
package. Do not run the package-creation command again if the package already
exists.

```bash
mkdir -p "$HOME/ROV - HiL and SiL/ros2_ws/src"
cd "$HOME/ROV - HiL and SiL/ros2_ws"
source /opt/ros/jazzy/setup.bash

ros2 pkg create \
  --build-type ament_cmake \
  --dependencies robot_state_publisher xacro \
  mini_rover_description
```

The important directory is now:

```text
ros2_ws/
└── src/
    └── mini_rover_description/
        ├── CMakeLists.txt
        ├── package.xml
        └── src/
```

Create directories for the robot description and launch file:

```bash
cd "$HOME/ROV - HiL and SiL/ros2_ws/src/mini_rover_description"
mkdir -p launch urdf
```

## 2. Describe the robot

Create `urdf/mini_rover.urdf.xacro` with the following contents. The dimensions
are in metres, mass in kilograms, and the inertia entries are deliberately
simple placeholders. They are adequate for visualisation only; do not reuse
them for Gazebo physics without a proper mass-property calculation.

```xml
<?xml version="1.0"?>
<robot xmlns:xacro="http://www.ros.org/wiki/xacro" name="mini_rover">
  <xacro:property name="body_length" value="0.40"/>
  <xacro:property name="body_width" value="0.30"/>
  <xacro:property name="body_height" value="0.12"/>
  <xacro:property name="wheel_radius" value="0.08"/>
  <xacro:property name="wheel_width" value="0.04"/>
  <xacro:property name="wheel_separation" value="0.34"/>

  <link name="base_link">
    <visual>
      <origin xyz="0 0 ${wheel_radius}"/>
      <geometry>
        <box size="${body_length} ${body_width} ${body_height}"/>
      </geometry>
      <material name="blue"><color rgba="0.1 0.3 0.8 1.0"/></material>
    </visual>
    <collision>
      <origin xyz="0 0 ${wheel_radius}"/>
      <geometry><box size="${body_length} ${body_width} ${body_height}"/></geometry>
    </collision>
    <inertial>
      <mass value="5.0"/>
      <inertia ixx="0.05" ixy="0.0" ixz="0.0"
               iyy="0.08" iyz="0.0" izz="0.10"/>
    </inertial>
  </link>

  <xacro:macro name="wheel" params="name y_position">
    <link name="${name}">
      <visual>
        <origin rpy="${pi/2} 0 0"/>
        <geometry><cylinder radius="${wheel_radius}" length="${wheel_width}"/></geometry>
        <material name="black"><color rgba="0.05 0.05 0.05 1.0"/></material>
      </visual>
      <collision>
        <origin rpy="${pi/2} 0 0"/>
        <geometry><cylinder radius="${wheel_radius}" length="${wheel_width}"/></geometry>
      </collision>
      <inertial>
        <mass value="0.5"/>
        <inertia ixx="0.002" ixy="0.0" ixz="0.0"
                 iyy="0.001" iyz="0.0" izz="0.002"/>
      </inertial>
    </link>
    <joint name="${name}_joint" type="continuous">
      <parent link="base_link"/>
      <child link="${name}"/>
      <origin xyz="0 ${y_position} 0"/>
      <axis xyz="0 1 0"/>
    </joint>
  </xacro:macro>

  <xacro:wheel name="left_wheel" y_position="${wheel_separation / 2}"/>
  <xacro:wheel name="right_wheel" y_position="${-wheel_separation / 2}"/>
</robot>
```

The robot's coordinate convention is the ROS convention: `x` forward, `y`
left, and `z` up. `base_link` is the root frame. The continuous wheel joints
let RViz animate the wheels without imposing position limits.

## 3. Validate the Xacro before building

Generate a URDF in `/tmp` and inspect it. This catches malformed XML and Xacro
expressions before a launch failure obscures the cause.

```bash
cd "$HOME/ROV - HiL and SiL/ros2_ws"
source /opt/ros/jazzy/setup.bash

ros2 run xacro xacro \
  src/mini_rover_description/urdf/mini_rover.urdf.xacro \
  --output /tmp/mini_rover.urdf

head -n 20 /tmp/mini_rover.urdf
```

Expected result: the command exits successfully and `/tmp/mini_rover.urdf`
contains a `<robot name="mini_rover">` element. A warning about a legacy Xacro
ordering mode should be treated as a reason to check the file, not ignored.

## 4. Install the package resources

Replace `CMakeLists.txt` with the following. The `install()` command is
essential: without it, `ros2 launch` cannot find the launch file and Xacro after
the package is built.

```cmake
cmake_minimum_required(VERSION 3.8)
project(mini_rover_description)

find_package(ament_cmake REQUIRED)

install(
  DIRECTORY launch urdf
  DESTINATION share/${PROJECT_NAME}
)

ament_package()
```

Add the runtime dependencies inside `<package>` in `package.xml`, immediately
before the `<export>` section:

```xml
<exec_depend>robot_state_publisher</exec_depend>
<exec_depend>joint_state_publisher_gui</exec_depend>
<exec_depend>xacro</exec_depend>
```

Keep the existing `ament_cmake` build-tool dependency and the existing package
metadata produced by `ros2 pkg create`.

## 5. Add a portable launch file

Create `launch/display.launch.py`. It uses the installed package share directory
rather than a path relative to the current terminal directory, so it works from
any directory after `colcon build`.

```python
from launch import LaunchDescription
from launch.substitutions import Command
from launch_ros.actions import Node
from launch_ros.parameter_descriptions import ParameterValue
from ament_index_python.packages import get_package_share_directory
from pathlib import Path


def generate_launch_description():
    package_share = Path(get_package_share_directory("mini_rover_description"))
    xacro_file = package_share / "urdf" / "mini_rover.urdf.xacro"

    robot_description = ParameterValue(
        Command(["xacro ", str(xacro_file)]), value_type=str
    )

    return LaunchDescription([
        Node(
            package="robot_state_publisher",
            executable="robot_state_publisher",
            name="robot_state_publisher",
            output="screen",
            parameters=[{"robot_description": robot_description}],
        ),
        Node(
            package="joint_state_publisher_gui",
            executable="joint_state_publisher_gui",
            name="joint_state_publisher_gui",
            output="screen",
        ),
    ])
```

## 6. Build and launch the robot

Build only this package on the first run. Source the overlay in every terminal
that needs to use it.

```bash
cd "$HOME/ROV - HiL and SiL/ros2_ws"
source /opt/ros/jazzy/setup.bash
colcon build --packages-select mini_rover_description
source install/setup.bash

ros2 launch mini_rover_description display.launch.py
```

Leave that terminal running. A small joint-state publisher window should open.
Moving either slider changes a wheel's angle, which is the intended input for
the next inspection step.

## 7. Inspect the robot in RViz2

Open a second terminal:

```bash
source /opt/ros/jazzy/setup.bash
source "$HOME/ROV - HiL and SiL/ros2_ws/install/setup.bash"
rviz2
```

In RViz2:

1. Set **Fixed Frame** to `base_link`.
2. Click **Add**, choose **RobotModel**, and add the display.
3. For **Description Source**, select **Topic** and use `/robot_description`
   if it is not selected automatically.
4. Click **Add**, choose **TF**, and add it.
5. Move the sliders in the joint-state publisher window.

Expected result: a blue rectangular chassis and two black wheels appear. The TF
display shows `base_link`, `left_wheel`, and `right_wheel`; turning a slider
rotates the corresponding wheel.

## 8. Verify the ROS 2 graph

In a third terminal with both environments sourced, run:

```bash
ros2 node list
ros2 topic list
ros2 run tf2_ros tf2_echo base_link left_wheel
```

Expected nodes include `/robot_state_publisher` and
`/joint_state_publisher_gui`. Expected topics include `/joint_states` and
`/tf`; `/robot_description` is also expected on current Jazzy installations.
`tf2_echo` should show a transform from `base_link` to `left_wheel` and update
when its slider moves.

Stop the exercise with `Ctrl+C` in the launch terminal, then close RViz2.

## What this has and has not proved

This exercise proves that the VM can generate and distribute a robot
description, calculate a transform tree, and render it in RViz2. It has not
proved any of the following:

- Gazebo starts or renders correctly;
- a robot has collision behaviour, gravity, traction, buoyancy, or dynamics;
- `/cmd_vel` makes a robot move;
- a camera, IMU, depth sensor, or thruster behaves realistically; or
- NATS, Cockpit, Control, Datalogger, or hardware integration works.

Those are separate milestones. The next exercise should add Gazebo Harmonic and
`ros_gz` to spawn a model, then add a controller and sensors only after the
basic simulator launch is repeatable.

## Troubleshooting

| Symptom | Likely cause | Check or correction |
| --- | --- | --- |
| `ros2: command not found` | Jazzy is not sourced. | Run `source /opt/ros/jazzy/setup.bash`. |
| `Package 'mini_rover_description' not found` | The package was not built or the overlay is not sourced. | Run the build command, then source `install/setup.bash`. |
| `xacro: command not found` | The Xacro package is missing. | Install `ros-jazzy-xacro`. |
| `ros2 launch` cannot find the launch file | `launch/` and `urdf/` were not installed. | Check `CMakeLists.txt`, rebuild, and source the overlay again. |
| No model appears in RViz2 | The fixed frame or robot description source is wrong. | Set Fixed Frame to `base_link`; add RobotModel and select `/robot_description`. |
| Wheel sliders do not change the view | `joint_state_publisher_gui` is not running or TF is hidden. | Check `ros2 node list`, add the TF display, and restart the launch file. |
| Build errors refer to an old description | Colcon is using stale output. | Correct the source, rebuild the selected package, and source the overlay in each terminal. |
